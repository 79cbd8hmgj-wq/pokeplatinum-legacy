# B1 — Donor asset integration is mandatory

**This overrides the earlier native-particle-only B1 pilot direction.** The full Opal donor database is a primary production input, not optional inspiration. Do not declare the cinematic battle overhaul complete by merely duplicating native emitters.

## Existing verified data

- `docs/visual_overhaul/DONOR_ASSET_CATALOG.json`: **64,841** donor records, including **49,054 Ranger 2**, **7,872 Diamond**, **5,784 HGSS**, **2,131 PMD Sky**.
- `docs/visual_overhaul/DONOR_CURATION_HANDOFF.md`: revised curation ledgers cover all 64,841, of which 55,157 usable, 9,578 rejected and 106 unresolved decode issues. Use **recovered curation overlays**, not stale baseline review flags.
- `docs/visual_overhaul/selection/OPPORTUNITY_POOL.json`: mined visual opportunities; `IMPLEMENTATION_QUEUE.json`: ranked candidates, specific hosts and source IDs.
- `docs/visual_overhaul/POKEMON_OPAL_ASSET_DIRECTION.md`: binding creative treatment modes: preserve, replace, enhance, composite, animate, create, discard. Favor an original Opal synthesis rather than a full donor-port.
- `docs/visual_overhaul/DS_DONOR_ASSET_PROGRAM.md`, `G5_DONOR_TECHNIQUE_AUDIT.md` and `CROSS_GAME_DONOR_MATRIX.md`: known decoding techniques and potential effects.

## Battle production path

1. **Mine exact battle opportunity records** with `battle_effects_particles`, `battle_backgrounds_hud`, `pokemon_animation_reference`, `pokemon_battle_sprites` and `menu_ui_frames` domains. Keep provenance keys and original donor identifiers. Assess Ranger 2 effect primitives, PMD Sky effect frames, HGSS UI animation and Diamond/Platinum-native materials.
2. **Curate a battle-specific shortlist**, recording donor source, record ID, decoded asset path, state (usable/rejected/decode issue), actual image/cell/palette/animation format, native dimensions, palette count, intended host and use mode. Do not guess graphic content from filenames alone.
3. **Build composite prototypes** using strongest compatible elements from different donor sources and Opal-designed geometry/color; preserve elemental hue while applying pearl/mineral-violet/gold to framing and UI.
4. **Integrate real game resources** via build/source asset pipelines and `res/moves/*/anim.s`, `res/graphics/battle` or verified `.spa` authoring tools. A preview PNG not wired into the ROM does not count.
5. **Audit file provenance and technical compatibility**: OBJ/BG bank, tile depth, palettes, dimensions, compression, NARC order, assembler reference, emitter/cell ownership and cleanup; build US rev0/rev1.
6. User handles **runtime/emulator acceptance**, not a release gate for source implementation. Mark those checks pending and continue other fully static work.

## Existing B1 five-move pilot status

Five native particle scripts (Shadow Ball, Thunderbolt, Ice Beam, Flamethrower, Energy Ball) were given simple secondary pulses as **temporary engineering smoke tests**. These are *not* the intended final complex effects. Replace/enhance them with evidence-backed donor-composite work after asset selection. Do not interpret their green CI as proof of cinematic quality.

## Completion criteria

For each completed effects/HUD batch supply a machine-readable ledger: host resource, donor record IDs, source graphics, treatment mode, source implementation, generated installed resources, palette/VRAM constraints, automated test evidence and pending owner emulator checks. Avoid hard-coded selections that bypass the 64,841-asset searchable collection.
