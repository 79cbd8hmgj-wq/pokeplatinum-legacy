# DAU1 provenance and legal release gate

Generated by `tools/visual_overhaul/dau1_unlock.py catalog` (sources table) - edit `report.py`, not this file.

## Release gate (owner decision required)

* **No ROM, base-ROM extraction, donor binary or bulk donor art is committed.** The catalog stores only paths, sha256 hashes, counts and budgets.
* The decomp projects' *source-code* licences (where a licence file exists at all) do not authorise redistribution of Nintendo / Game Freak / Spike Chunsoft / Creatures artwork. Every pool below is therefore `asset_license: UNVERIFIED`.
* The small (<= 60 cell) evidence excerpts of decoded donor frames (`*_excerpt.png`) are **local-only**: they were removed from version control in DAU2 (owner decision) and are written to `build/dau1_excerpts` by `catalog`. They are not cleared for release. Full galleries are also written to `build/` (git-ignored).
* Converted Opal FX sheets produced by `dau1_unlock.py convert` go to `build/` and are not installed into `res/`; installing one needs a separate, reviewed change (and the same licence decision).

## Per-resource provenance

Every catalog unit carries `source` (repo-relative path), `sha256` (primary input bytes; for multi-file units the hash of the member hashes) and, for multi-file units, a `members` list of `{name, sha256, size}`. Container members are addressed `path#member-index`. `visual_sha256` hashes the decoded RGBA frames, so identical art in different donors (or re-encoded) is detected without storing any pixels.

## Third-party format knowledge and reference implementations

* NARC / Nitro 2D (NCLR, NCGR, NCER, NANR) layouts: public NitroSystem / community documentation; verified pixel-for-pixel against the existing in-repo Ranger renderer (`render_ranger_ncer_preview.py`) on 134 cells.
* SPL `.spa` layout: derived from 602 real sample files (pokediamond) plus the decomp struct `include/library/spl_texture.h`; each file is validated structurally (blocks tile the file exactly; texture byte counts equal width x height x bits / 8).
* PMD effect-WAN layout: public community documentation of the game's file layout. The implementation here is original. As an *independent cross-check only*, SkyTemple's `skytemple-files` (GPL-3.0) was installed in a throw-away virtualenv outside the repository and compared against this decoder: 259 sprites / 29,365 pieces, 0 differences in piece counts, geometry or pixel masks. No SkyTemple code is vendored, imported by the tools, or required by CI.
* Crystal recipes: the project's own assembly tables (`data/battle_anims/*.asm`) - nothing is inferred.
