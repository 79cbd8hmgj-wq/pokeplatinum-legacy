# DAU2 - SPL emitter-motion research (HGSS + Diamond)

Generated by `tools/visual_overhaul/dau2_curate.py emitters`. **Tooling and evidence only** - the Platinum battle renderer, move scripts and `res/` are untouched, and no runtime interpreter is added.

## What was achieved

* `.spa` emitter blocks (`SPLResourceHeader` + optional scale / colour / alpha / texture-animation / child blocks + up to six behaviours) are parsed field-by-field by `tools/visual_overhaul/dau2/spl_emitter.py`. The layout is not guessed: it is the one Platinum's own `lib/spl` uses (`SPLManager_LoadResources`, `spl_resource.h`, `spl_behavior.h`).
* An offline replay (`spl_sim.py`) ports the per-frame state update of `lib/spl` (spawn accumulator, emission shapes, initial velocity/scale/life, drag, behaviours, curves, children) and the `SPLRandom` LCG, and a deterministic renderer draws it (`emitter_preview.py`).
* Three representative effects (contact / element / status, all real P1/P2 moves) were replayed in **every game that carries them** and exported as declarative `emitter_recipe.json` files.

`EMITTER_PREVIEW_VERIFIED` means: an offline replay exists and passes its invariants (spawn schedule re-derived independently from the header, particle ages within life, determinism, DS quad limit). It does **not** mean the replay was compared with a runtime capture - none was available (no emulator/hardware in this environment). `CANDIDATE_REVIEWED` is 0 because only the owner can review. `BLOCKED_SOURCE` are the 72 HGSS entries listed in `filesystem.sha1` that only exist after extracting a legally owned ROM; DAU1 also lists which of the 645 present HGSS archives hold blank/4x4-compressed textures.

## Evidence that the parse is right (independent of 'it ran')

1. **Exact tiling.** For every archive the emitter records, whose sizes depend on the optional-block flags, consume the emitter block to the byte (`parse_emitters` fails closed otherwise). 1874 archives tile exactly; a wrong struct size or flag bit would break this for almost every file.
2. **Cross-references resolve.** Every texture index (base, texture-animation list, child) is below the archive's texture count; no divisor field (`emission_interval`, `loop_frames`, random-behaviour interval) is 0. These are fields the game divides by.
3. **Value distributions match the source's semantics.** Across all emitters, fraction with:

   * air_resistance_is_128_(neutral_drag_in_lib/spl): 0.5637
   * aspect_is_1.0: 0.7211
   * base_alpha_le_31: 1.0
   * user_flags_zero: 1.0
   * emission_count_is_whole_number: 0.954
   * loop_frames_ge_1: 1.0
   * emission_interval_ge_1: 1.0
   * particle_life_between_1_and_600: 1.0

   (5519 emitters.) E.g. `air_resistance == 128` being the dominant value is exactly what `lib/spl`'s `airResistance + 0.09375` with `>> 9` predicts for 'no drag'.
4. **Cross-game consistency.** The same effect parsed from Platinum, Diamond and HGSS gives identical emitter records (table below). This shows the games share the data and the parser is stable across three independently shipped files; it is a consistency check, not independent proof of what a field means (the meaning comes from `lib/spl`).
5. **Reserved/padding fields are NOT evidence.** They contain non-zero junk in the shipped files (uninitialised padding written by the particle editor); they are kept verbatim under `unknown` and never interpreted.

## Semantics and their source

| Behaviour | Source in Platinum `lib/spl` |
|---|---|
| resource layout / optional-block order | `lib/spl/src/spl_manager.c:SPLManager_LoadResources` |
| header and flag bit layout | `lib/spl/include/spl_resource.h:SPLResourceHeader/SPLResourceFlags` |
| behaviour record layouts | `lib/spl/include/spl_behavior.h` |
| emitter start/emit gating, per-frame update order | `lib/spl/src/spl_emitter.c:SPLEmitter_Update, spl_manager.c:SPLManager_Update` |
| spawn count (fractional accumulator), emission shapes, initial velocity/scale/life | `lib/spl/src/spl_emit.c:SPLEmitter_EmitParticles` |
| child particles | `lib/spl/src/spl_emit.c:SPLEmitter_EmitChildren` |
| scale/colour/alpha/texture curves | `lib/spl/src/spl_anim.c` |
| gravity/random/magnet/spin/collision/convergence | `lib/spl/src/spl_behavior.c` |
| RNG | `lib/spl/include/spl_random.h:SPLRandom_Next` |
| billboard size = 2*scale (quad -1..1) | `lib/spl/src/spl_draw.c:SPLDraw_Billboard/SPLUtil_DrawXYPlane` |

## Unknown / approximated (explicitly NOT claimed)

* Which emitters a move creates, when and where - this lives in the battle scripts / particle-index tables, not in the `.spa`.
* Emitter user callbacks and per-frame position/velocity driven by the battle engine (e.g. travelling projectiles).
* The real battle camera and world-to-screen scale (previews use an orthographic front view with a fitted scale, printed per recipe).
* NitroSDK fixed-point sin/cos tables and vector normalise (rounded `math.sin` and float normalise stand-ins): counts and timing are unaffected; placement can differ by a few LSBs. The rotation sign convention of the spin behaviour (`MTX_Rot*33`) is unverified, so a spin could be mirrored.
* Emitter axis tilt for circle/cylinder/hemisphere emission, polygon / directional / view-space draw types (flags are exported, not simulated).
* The initial `gSPLRandomState` (seeded at run time); the replay uses a fixed seed, so particle positions are one plausible instance, not THE instance.
* Texture VRAM placement, polygon-ID/depth rules, translucency sort order, and any hardware performance claim: counts only (see each recipe's `resource_estimate`).
* 4x4-compressed textures (format 5) are not decoded (DAU1 limit); particles referencing them are not drawn in previews and are listed under `undecoded_texture_indices`.
