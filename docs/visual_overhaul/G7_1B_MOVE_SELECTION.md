## 2. What changed (asset/table only)

* `src/overlay011/move_palettes.c` — the 19 per-type tables are regenerated by
  `tools/visual_overhaul/generate_move_select_palettes.py` from the retail
  hue/saturation/value of each type's base color (type identity preserved):
  * ramp entries 2-9: higher-contrast light → deep steps plus a pale highlight;
  * entry 10 (outline): retail `RGB(6,6,6)` gray → deep navy `RGB(1,3,7)`,
    matching the G7.1A keys;
  * entries 13/14 (label plate edge/fill): retail cream (`28,26,13` /
    `30,29,21`) → cool slate / pale blue-white (`17,21,26` / `29,30,31`), so
    the plate reads as a clean data panel on the dark deck. Luminance is
    equivalent to the cream it replaces, so the unchanged label text keeps its
    contrast, and the PP warning colors (gold / orange / red) separate better
    from a cool plate than from yellow-cream.
* `pl_batt_bg.narc` member #242, **bank 14** — the shared "empty/unavailable"
  ramp is now a muted slate with a dim plate. Empty move slots and cleared
  target slots therefore read as recessed/disabled by *value and the absent
  bright plate*, not only by color.
* `generate_battle_command_ui.py` gained bank 14; the validator gained
  move-palette checks.

No tile pixel, tilemap, cell, touch rect, label/OAM position or C logic changed,
so slot mapping, name/type/PP presentation, empty/disabled behaviour and
D-pad/touch handling are byte-for-byte the same code paths as G7.1A.

## 4. Deferred, with reasons

* **Physical / special / status icon.** The data path is cheap
  (`MoveTable_LoadParam(move, MOVEATTRIBUTE_CLASS)`), and the lifecycle hooks
  already exist (`categoryIconSprites`, `FreeCategoryIcons`, press nudges,
  `CategoryIcon_LoadChar`, icons share the type-icon cell/palette). It is *not*
  done here because the 96-px label plate is already full: name row
  (up to ~80 px) above a bottom row holding the 32-px type badge, the "PP"
  label and the `xx/xx` count. Adding a 32×16 icon needs either a smaller PP
  block or a changed plate layout (tilemap + OAM positions + hitbox review),
  and the sprite creation path cannot be exercised without runtime testing in
  this environment. Plan: take it together with a plate re-layout after the
  owner reviews the palette pass.
* **Focused-slot brightness pulse.** Needs per-frame palette blending in
  `BattleSystem_Cursor_Moves` with cleanup on press/exit — a small but real
  C-side state machine. The G7.1A bracket already provides the shape cue; the
  pulse is optional and left until the owner confirms it is wanted.
* **Slot tile reshaping** (chamfers/texture): shares tile classes with the
  command keys; defer until the owner has judged the palette pass.
