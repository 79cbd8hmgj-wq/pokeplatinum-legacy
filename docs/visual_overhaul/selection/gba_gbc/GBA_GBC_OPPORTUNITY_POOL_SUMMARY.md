### map_location_preview -> reference_only, subsumed
28-entry table (20 cave, 8 forest), 21 distinct art sets, two trigger paths (cave: fade-through-black in `fldeff_flash.c`; forest: alpha crossfade in `overworld.c`), first-visit hold 120 frames vs 40 on repeat, B skips, quest-log playback suppressed, table reused by the region-map dungeon panel. Platinum has only the map-name popup (`map_name_popup.c`) and no preview layer, which is the same gap already carried by `opp:hgss/map_location_preview`. FireRed corroborates that opportunity and supplies four small design details (visit-gated hold, skip, per-area presentation style, second UI consumer). It does not add a capability, so no duplicate record is promoted. DS records were not modified; the cross-reference is stored on the FireRed record (`cross_reference`).

### animated_palette_sequences -> reference_only
Elite Four: 12 sixteen-colour palettes, 11 timers (40 then ten x 12 = 160 ticks per cycle), palette 11 is the non-looping settled state. Champion room: 9 palettes, 8 timers (20 then seven x 8 = 76 ticks), palette 8 is the settled state. Both write BG palette slot 7 and re-tint it each step; only colour indices 3 and 8-15 change. Ticks only while no fade is active, the player has entered, no battle is running and the quest-log tint is off; cancelled by flag and by menu/item use. Platinum's field is 3D, with a native G3D prop-animation manager (loop, reverse, pause, frame control), area light templates and a generic palette-buffer API, so the mechanism has an equivalent and the donor contributes only timing shape. Not checked: whether Platinum's own League rooms use these hosts for lighting.

### interactive_object_states -> split, both reference_only
- Generic half: progress variable (0-10) drives an 11-stage grey-to-orange 4-colour ramp on OBJ palette 10, re-derived on return-to-field, reset to stage 0 when the step cap is exceeded. The variable is zeroed on every map transition, so it is visit-scoped, not long-term progression. Platinum already drives stateful props this way (Pastoria Gym via `MapPropAnimationManager`).
- Event-specific half: 11 fixed coordinates, 10 step caps, 5-frame hops (60 on reset), per-hop SE, destroy sequence with camera shake, white flash and four 8x8 fragments. Emerald already has the destroy/shake/fragment choreography (closed as reference_only in B1), so this half is a duplicate there; only the step-capped puzzle is new and has no Platinum host. `field_special_scene.c` contains no Deoxys code (21-line porthole stub).
